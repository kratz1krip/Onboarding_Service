# Правила командной работы

## Git-протокол (GitHub Flow)

- Стабильный код хранится в ветке `main`, прямые изменения в нее запрещены.
- Новая функция – ветка `feature/ONB-<номер>-<описание>`, например `feature/ONB-87-mentor-assignment`.
- Исправление дефекта – ветка `bugfix/ONB-<номер>-<описание>`, например `bugfix/ONB-112-checklist-department-filter`.
- Ветка живет не дольше спринта и удаляется после слияния.

## Pull Request

Pull Request открывается, когда модуль собирается в CI, покрыт тестами, а миграция БД проверена на тестовой копии. Если меняется API, в том же PR обновляется OpenAPI-спецификация. Слияние – после одобрения минимум одного коллеги и прохождения тестов.

## Чек-лист Code Review

1. Сотрудник получает только свой чек-лист: идентификатор берется из токена авторизации, а не из параметра запроса.
2. Персональные данные новичка не попадают в логи и в ответы API, которые видит наставник.
3. Изменение структуры БД оформлено миграцией EF Core, новая бизнес-логика покрыта тестами xUnit.
